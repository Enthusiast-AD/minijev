01Project Overview

This project builds a Banking Customer Intent Classifier — a machine learning model that reads a customer's text message and automatically identifies what the customer needs out of 77 possible banking categories.

  • "My card hasn't arrived yet" → card_arrival
  • "I forgot my PIN" → pin_blocked
  • "What is today's exchange rate?" → exchange_rate

This type of system is used in real-world banking chatbots and customer support automation to route customers to the right department without human intervention.

💡

Technology used: TF-IDF (text feature extraction) + MLP Neural Network (classification), implemented using Python and scikit-learn.

02Problem Statement

🎯

Given a customer's natural language query, automatically classify it into one of 77 predefined banking intent categories.

Why is this hard?

  • There are 77 very similar categories (e.g., card_not_working vs. virtual_card_not_working vs. contactless_not_working)
  • Customers write in many different ways: "my card stopped working", "can't use card", "card is rejected" — all mean the same thing
  • Some categories have very similar vocabulary but different meanings

This is a classic multi-class text classification problem.

7.2 TF-IDF: Converting Text to Numbers

Neural networks cannot process raw text — they need numbers. TF-IDF (Term Frequency–Inverse Document Frequency) converts each text into a numerical vector.

What is TF-IDF?

TF (Term Frequency): How often a word appears in a sentence. "card card not working card" → card has TF = 3/5 = 0.6

IDF (Inverse Document Frequency): How rare the word is across all documents. Common words ("the", "is") → low IDF. Rare words ("compromised") → high IDF.

TF-IDF Score = TF × IDF
TfidfVectorizer(
    max_features=5000,    # Use top 5000 most important words
    ngram_range=(1, 2),   # Use single words AND word pairs (bigrams)
    min_df=2,             # Ignore words appearing in < 2 documents
    sublinear_tf=True,    # Apply log(1+tf) for smoother weighting
)

Why ngram_range=(1,2)? Captures phrases like "not working", "card stolen", "exchange rate" which have specific meaning as a pair.

7.3 ANN Model Architecture

Input Layer → 5000 neurons (TF-IDF features) ↓ Hidden Layer 1 → 256 neurons [ReLU activation] ↓ Hidden Layer 2 → 128 neurons [ReLU activation] ↓ Output Layer → 77 neurons [Softmax → probabilities] ↓ Predicted Class (1 of 77)
TermSimple Explanation
ReLUActivation function: f(x) = max(0, x). Helps the network learn complex patterns.
Adam OptimizerSmart version of gradient descent. Adapts learning rate automatically.
L2 RegularizationPenalty for large weights — prevents overfitting (memorizing training data).
Early stoppingAutomatically stops training when validation accuracy stops improving.
EpochOne complete pass through all training data.

7.4 Train/Validation/Test Split

Total Training Data (10,003 samples)
  ├── 85% → Training Set   (8,502 samples)  ← model learns from this
  └── 15% → Validation Set (1,501 samples)  ← check during training
Separate Test Set (3,080 samples)  ← final fair evaluation

7.5 Training Process

  1. Forward pass — send input through network, get prediction
  2. Compute loss — compare prediction with true label (cross-entropy loss)
  3. Backward pass — calculate how much each weight contributed to the error
  4. Update weights — nudge each weight in the direction that reduces error
  5. Repeat until convergence or early stopping triggers (~15 epochs)

08Evaluation Metrics — What They Mean

8.1 Accuracy

"Out of ALL predictions, how many were correct?"
Accuracy = Correct Predictions / Total Predictions = (TP + TN) / (TP + TN + FP + FN)

Our result: 87.53% — the model correctly identified the intent in 87.53 out of every 100 messages.

Limitation: If one class had 99% of examples, a model always predicting that class gets 99% accuracy but is useless. That's why we also need Precision, Recall, and F1.

8.2 Precision

"Of everything the model said was class X, how many actually WERE class X?"
Precision = TP / (TP + FP)

Example: Model predicted "card_arrival" 100 times, 88 were actually card_arrival → Precision = 88%.

Our result: 88.29% (Macro-averaged across all 77 classes)

8.3 Recall

"Of all the ACTUAL examples of class X, how many did the model correctly find?"
Recall = TP / (TP + FN)

Example: 100 actual "card_arrival" messages, model found 88 → Recall = 88%.

Our result: 87.53% (Macro-averaged across all 77 classes)

8.4 F1-Score

"The balanced average of Precision and Recall."
F1 = 2 × (Precision × Recall) / (Precision + Recall)

A high F1 means both Precision and Recall are high. Our result: 87.65% (Macro F1)

8.5 Macro vs Weighted Average

AveragingHow it worksWhen to use
MacroAverage across all classes equallyBalanced dataset ✅ (our case)
WeightedAverage weighted by class sizeImbalanced datasets
MicroCalculate globallyWhen total counts matter

8.6 Confusion Matrix

A confusion matrix shows what the model confused. Each cell [i][j] says: "When the real class was i, the model predicted j this many times." Diagonal = correct predictions. Off-diagonal = mistakes.
